# Ponytail 按需编码能力

Ponytail 是全栈研发入口在**实现、重构和代码审查**中按需使用的外部能力，不是可与父入口竞争触发的第二个 Skill。先理解需求、代码流和真实约束，再在以下阶梯的第一处可靠解停止：

1. 这项能力不需要存在：不做。
2. 仓库已有实现：复用，不重写。
3. 标准库可满足：使用标准库。
4. 平台原生能力可满足：使用原生能力。
5. 已安装依赖可满足：复用依赖。
6. 一行或一个小函数可满足：写最小实现。
7. 只有前述方案都不成立时：新增最小、可验证的实现。

## 何时激活

- 写功能、修 Bug、重构、性能改进、代码审查：应用能力阶梯；已安装 Ponytail 插件时按需调用其对应能力。
- 只读解释、需求收集、纯规划、平台查询、日程或文档操作：不激活 Ponytail。
- 新产品或重要交互：先遵循工程原则完成必要的原型或规格判断；Ponytail 只约束之后的实现选择。

## 不可裁减的底线

极简只针对不必要的实现。输入校验、权限和信任边界、数据丢失保护、错误处理、可访问性、回归检查以及用户明确的验收条件不得删除。理解完整调用链后再缩小 diff；共享根因优先于在各调用方添加 guard。

## 插件、降级与审阅

`DietrichGebert/ponytail` 以 MIT 许可提供 Codex 插件及生命周期 Hook。本仓库不复制其 Skill 文件或 Hook，也不静默安装插件、改变默认模式或信任 Hook。

当用户明确安装并在 Codex `/hooks` 审阅信任后，父入口可在编码任务中使用该插件的 `@ponytail`、`@ponytail-review` 和 `@ponytail-audit` 等能力。插件不可用时，父入口仍直接执行本文件的能力阶梯；这保证远端环境、CI 和未安装插件的用户保持相同行为底线。
